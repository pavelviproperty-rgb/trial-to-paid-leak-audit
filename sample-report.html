Executive diagnosis

The leak is probably not generic churn. The first paid invoice after trial is failing more often than later renewals, and product access appears to stay active for some accounts while Stripe is `past_due`. That means the first fix is measurement and access-state sync, not a broader dunning rewrite.

Facts used

  • Trial length: 14 days.
  • First-month price: $49.
  • First paid invoice failure rate: 11%.
  • Normal renewal failure rate: 3%.
  • Access state is updated by webhook, not by polling.

Unknowns

  • Exact decline-code mix for failed first invoices.
  • Whether all webhook failures are retried successfully.
  • How many failed first invoices belong to active users.
  • Whether reminder timing differs for trial-ending users.

Top 3 fixes

  • Add a dedicated `first_post_trial_invoice_failed` segment instead of mixing it with trial conversion or normal renewal recovery.
  • Log `invoice.status`, `subscription.status`, and app access state on the same row for each first paid invoice after trial.
  • Send the first recovery reminder only after confirming whether the user still has product access and recent activity.
